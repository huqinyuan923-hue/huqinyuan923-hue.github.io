这个站点的起点是我自己的记忆：刚开始用 GitHub 的时候，官方文档我读不进去，网上的中文教程开口就是「仓库」「暂存区」「工作区」，每篇都默认你已经懂了前十个名词才讲第十一个。后来我算是会用了，但那种"每个字都认识、连起来不知道在说什么"的感觉一直记得。

所以有了 [GitHub 新手村](https://guide.adcakeyuan.top/)——一个给完全没碰过 GitHub 的人看的入门站。整个站只有一条写作纪律：**不堆术语，能用生活比喻就不用专业词**。Git 是游戏存档，Branch 是平行世界的草稿纸，Fork 是把别人的菜谱抄一份回家，Pull Request 是"我照你菜谱改了道菜，你尝尝要不要收进菜谱"。

## 站里有什么

四个页面。首页是主文档：Git 和 GitHub 的区别、十个核心概念的比喻卡、十二项功能的地图（按新手/进阶/高级分级）、八步上手教程、二十四条术语速查表。两个实战页：「GitHub Pages 三步免费建站」和「提交人生第一个 PR」——后者从找 good first issue 讲到怎么应对审核，还写了一条红线提醒：不要刷 PR。第三个是 AI 编程工具指南，讲 ZCode、OpenCode、DSH 三款工具怎么用，附一份十二个词的黑话小词典。

纯静态 HTML，零框架零构建，四个页面加样式合计两千三百行。访客打开首页，跟着 Hero 的按钮进教程，或者直接跳到某个 Part。

## 最难的不是技术

写这个站的时候，代码上的挑战其实很小。真正花时间的是措辞：每一个概念我都要先写一版"正常"的解释，然后逼自己回答"这句话里有没有还没讲过的词"，有就继续拆，直到拆到生活语言为止。「暂存区」最后讲成了"先把要带的东西放进背包，确认齐了再出门"。

为了让页面本身也像 GitHub，我直接把 CSS 变量抄成了 GitHub Dark 的官方配色（`#0d1117` 那套），还用纯 CSS 画了一个假 GitHub 仓库界面——红黄绿三个窗口圆点，文件列表带提交说明和时间，然后在旁边用编号标注每个界面元素对应 Part 3 的哪个概念。零图片素材，访客先"看熟"这个界面再注册，到真站点就不会两眼一抹黑。

## 一天写完，然后只补了一个文件

这个项目的提交史短得不像话：上午 11:12 一次提交把整个站写完，晚上 20:34 加了一个 CNAME 文件绑定域名，结束。没有返工，没有迭代——内容在动手前就在脑子里过了很多遍。

倒是有个值得记的细节：教程里"AI 工具"那一页的示例 AGENTS.md，我写进去的两条约定是"不要动 .shots/ 目录和任何密钥文件"和"提交信息用中文"。这两条其实就是我自己开发时的约定——这个站的截图验证流程、安全扫描配置，全都是照着那页教程里讲的方法跑的。教材里的每一条建议，我自己都是先用过的。
