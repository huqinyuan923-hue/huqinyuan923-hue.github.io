这个项目的起点不是「我要做一个 ChatGPT」，而是一个更小的问题：**一个语言模型的最小闭环，到底由哪些零件组成？**

我把问题拆成四件事：语料、tokenizer、Transformer、训练循环。四件都在这个项目里完成，不下载预训练权重，不调任何 API。最后再加一件：把权重搬到浏览器里，让读者打开网页就能看到它写字。

模型很小，2.23M 参数；语料也不大，316,810 个字符。它写不出完整文章，但它把「文本 → 训练 → 权重 → 推理」这条链路完整走了一遍。这篇文章记录的就是这条链路。

## 语料：把这个博客自己喂给模型

我没有去网上找通用语料，因为那样模型学到的是别人的文风，和这个博客没有关系。语料是从本地项目里现抽的，`extract.mjs` 做三件事：

1. 扫 `data/blog` 下全部文章，去掉 frontmatter、JSX 标签和代码围栏标记；
2. 收 cha-lang 的 README、系列大纲和示例程序；
3. 收 `C:/works` 下各项目的 README。

最后得到 **75 篇文档、316,810 个字符、2,081 个不同字符**。中文占 27.2%，剩下的主要是英文、代码和 Markdown 符号。出现频率最高的字符是空格，然后是 `e`、换行、`t`、`o`——这个分布已经很诚实地说明了语料的构成：它不是一个纯中文语料，而是一个「博客 + 代码仓库」的混合体。

这带来一个后面会反复出现的副作用：模型会把 Markdown 的星号、代码块的反引号、JSON 的花括号一起学进去。它写出来的东西经常像「博客和代码的混血」，这是语料决定的，不是模型突然有了个性。

## 字符级 tokenizer：2,081 个 token 的极简方案

我没有训练 BPE，也没有用现成的 tokenizer。做法简单到只有三行：

```python
corpus = open('corpus.txt', encoding='utf-8').read()
chars = sorted(set(corpus))
stoi = {c: i for i, c in enumerate(chars)}
```

**每个字符就是一个 token**。中文不需要分词，「字节码」是 3 个 token；代码里的 `{`、`}`、`*` 也各自是一个 token。这样做的好处是没有 tokenizer 的训练和对齐问题，所有字符一视同仁；坏处是同样一段话占的 token 更多，每个 token 承载的语义也更少。

对 2M 参数的小模型来说，这个取舍是合适的：它把「分词」这个变量彻底消掉了，模型学不好就只能是模型本身的问题，不会甩锅给 tokenizer。

## 模型：2.23M 参数，够小才跑得动

架构是标准的 decoder-only Transformer，配置如下：

| 项目     | 值                              |
| -------- | ------------------------------- |
| 层数     | 4                               |
| 注意力头 | 4                               |
| 隐藏维度 | 192                             |
| 上下文   | 256 个字符                      |
| 词表     | 2,081                           |
| 参数量   | 2,228,544                       |
| 权重绑定 | 输入 embedding 与输出 head 共享 |
| Dropout  | 0.15                            |

每个 block 是 Pre-LN 的因果自注意力 + GELU MLP：

```python
mask = torch.triu(torch.ones(T, T, dtype=torch.bool), 1)
h = self.ln1(x)
a, _ = self.attn(h, h, h, attn_mask=mask, need_weights=False)
x = x + a
x = x + self.mlp(self.ln2(x))
```

输入 embedding 和输出 head 共享同一份权重，这是从 nanoGPT 学来的做法：既省参数，也让输入和输出在同一个向量空间里。2,228,544 个参数，用 int8 存大约 2.2MB——比一张手机照片还小。

## 训练：CPU 上的 2,500 步

机器没有独立 GPU，全程 CPU 训练（PyTorch 2.14.1+cpu，24 线程）。超参也很朴素：

- batch 16，上下文 256，每步 4,096 个 token；
- AdamW，学习率 3e-3，100 步 warmup 后余弦衰减；
- dropout 0.15，梯度裁剪 1.0；
- 训练 2,500 步，大约 1,024 万个 token，相当于在 30 万字符的训练集上过 34 遍左右。

每 100 步在验证集上算一次 loss，只有验证 loss 创新低时才保存 `ckpt.pt`。最后 best val 是 **3.235**（发生在第 2,500 步），最终 train loss 约 **2.224**，训练循环耗时 **37.0 分钟**。

作为参照：词表是 2,081，随机猜的交叉熵是 ln(2081) ≈ 7.64。best val 3.235 意味着模型对下一个字符已经有了一定的把握，但离「会写文章」还很远。

## int8：把模型压到 2.2MB

训练完的 `ckpt.pt` 是 fp32，约 8.9MB。导出时我对每个二维权重矩阵做了**按行对称量化**：

```python
amax = np.abs(w).max(axis=1)
scale = np.where(amax > 0, amax / 127, 1.0).astype(np.float32)
q = np.rint(w / scale[:, None]).clip(-127, 127).astype(np.int8)
```

每个输出行有自己的 scale，`w ≈ q * scale`。LayerNorm 的权重、bias 这些一维小张量保留 fp32，因为它们占比很小，量化收益不大。最终 int8 权重 **2,218,176 字节**，加上元数据和 scale，整个二进制约 **2.2MB**。

量化对精度的影响：

| 版本 | 验证 loss |
| ---- | --------- |
| fp32 | 3.2636    |
| int8 | 3.2646    |

（训练日志里的 best val 用随机窗口估计；这里的 fp32 / int8 是导出脚本在固定的 24 个验证窗口上复测的，绝对值不能逐位对比。）

差了 0.0010。对这样一个本来就不追求精度的模型来说，这个代价可以忽略。**int8 只是省空间和带宽，它不会让模型变聪明。**

## 浏览器里手写一次前向

页面没有用 ONNX Runtime，也没有用 WebGPU：2.2M 参数太小了，手写循环足够快，还能少一个依赖。

核心是一个 int8 点积：

```js
for (let o = 0; o < rows; o++) {
  let s = 0;
  for (let i = 0; i < cols; i++) s += q[o * cols + i] * x[i];
  out[o] = s * scale[o] + bias[o];
}
```

生成时用了 KV cache：每个新字符只算自己的 q/k/v，然后和缓存里的历史 k/v 做注意力，而不是把整个前缀重新跑一遍。否则生成 160 个字符的计算量会翻几十倍。

```js
const cacheBase = (layer * nHeads + head) * block * headDim;
kCache[cacheBase + pos * headDim + d] = k[d];
```

实现完之后我做了两次数值对齐：同一段 prompt，PyTorch 和 JS 的最后一位 logits 最大误差 **6.676e-6**；用贪心解码连续走 24 步，**24/24** 个 token 一致。这个误差来自浮点累加顺序和 GELU 的 erf 近似，已经足够小。

页面跑在 Web Worker 里，权重通过 fetch 流式加载，生成时逐字 postMessage 回主线程，所以主线程不会卡。这台机器上的 Chromium 实测大约 **98.1 tok/s**（160 个字符约 2 秒），手机和低功耗设备会慢一些。

## 它不会做什么

必须把话说清楚：这是一个**教学模型**，不是产品。

- 它不会回答问题，也没有指令微调。你给它「帮我写个周报」，它只会顺着字符概率往下编；
- 上下文只有 256 个字符，写不了长文；
- 语料里 27.2% 是中文，其余大量是代码和 Markdown，所以输出会偏格式、偏碎片；
- 它可能复述训练语料里的句子。2M 参数记不住整篇文章，但记住局部片段是可能的；
- best val 3.235 仍然不低，错误是常态。

如果你需要一个能完成任务的模型，去用 API；如果你想亲眼看看 LLM 内部的矩阵乘、注意力和采样长什么样，这个 demo 的前向代码全部在浏览器里，可以直接读。
